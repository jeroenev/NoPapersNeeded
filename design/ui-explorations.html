no-papers-needed — UI overhaul explorations

Four design directions for the same core surfaces: the Library (home) on desktop and mobile. All directions replace the current drawer-only navigation with adaptive navigation (bottom bar / nav rail / permanent sidebar) and a real design-token system. Mockups are stylized wireframes — layout, hierarchy, and mood, not pixel-final art.

Evolution, not revolution — the current identity, refined.

Keeps the existing indigo accent and paper-white neutrals but adds warmth, a proper type scale, tonal surfaces, and adaptive navigation: icon rail on desktop, bottom bar on mobile. Lowest-risk direction; mostly a theming + nav-shell change.

  • Type: Fraunces (display) + Newsreader/Inter (body), small-caps labels
  • Nav: labeled sidebar on desktop; mobile keeps drawer or a minimal top-level list

Desktop-first, keyboard-first, information-dense. Dark by default.

Treats the app like a professional tool (think mail client / IDE): three-pane desktop layout with nav, document list, and always-visible preview + metadata. Monospace metadata, visible keyboard shortcuts, compact rows. On mobile it collapses to a dense list with tabs; the preview pane becomes the existing detail screen.

System

  • Type: Inter 13px base + JetBrains Mono for dates/hashes/counts
  • Nav: labeled sidebar with counts; mobile uses top tabs, no drawer

System

  • Type: Manrope, heavy weights for headers, generous letter-spacing control
  • Nav: floating pill bottom bar (phone), padded rail (desktop)
  • Depth: soft tinted shadows, no borders; 20–24px radii; XL touch targets

Pros

  • Most approachable for non-technical household users
  • Great fit for the scan-first mobile flow (big FAB, greeting header, review nudges)
  • Chips-as-primary-filter matches how people actually browse tags

Cons / risks

  • Can feel toy-like on a 27" monitor; desktop needs restraint (smaller radii, denser grid)
  • Soft shadows are more expensive to render and tricky in dark mode
  • Playfulness may clash with "serious archive of legal documents"

Compose mapping

  • Standard M3 with custom Shapes (extraLarge everywhere) + shadow ambient color
  • Docked pill bar = NavigationBar in a padded, clipped Surface
  • Greeting/stat header composable reused across both form factors

These mix well: A or B as the visual language combined with C's three-pane layout on expanded window sizes only is likely the strongest overall — a calm paper identity that becomes a power tool when the window is wide, and a clean bottom-bar app on the phone.

Recommended implementation approach

The current theme is a single 64-line file and adaptivity is one 840dp helper used in three places — both are cheap, central seams to rebuild on. Phase the overhaul so every step ships independently:

Design tokens first

Expand ui/theme/Theme.kt into color + Typography + Shapes + spacing tokens for the chosen direction. Add an in-app light/dark/system toggle. Zero layout changes — instant visual win, trivially revertable.

Adaptive foundation

Add material3-adaptive + material3-adaptive-navigation-suite. Replace Responsive.kt's 840dp breakpoint with window size classes (compact/medium/expanded) at its three call sites.

Navigation shell

Replace the drawer with NavigationSuiteScaffold: bottom bar on compact, rail on medium, permanent sidebar on expanded. Saved views and secondary destinations move into the Library screen or an overflow sheet.

Library screen

Restyle cards/chips/search per the chosen direction. If going toward Workbench: introduce ListDetailPaneScaffold on expanded widths so selecting a doc previews in-pane (reuse BrowseContext).

Detail, Settings, and the rest

DocDetail metadata panel, then Settings (851 lines — split into per-section composables while restyling), then Tags/Trash/AI screens which are small.

Polish pass

Motion (shared-element thumbnail transition list→detail), empty states, snackbar/banner styling, desktop keyboard-shortcut discoverability (⌘K palette if Workbench).

Verify each phase with the CI order: spotlessCheck → detekt → mise test-fast → compile android+desktop. ViewModels are untouched throughout — this is a pure UI-layer overhaul.
